# 에버그로우(EverGrow) 스마트팜 시뮬레이터

농업 인구가 늙어가면서 일손이 줄어드는 문제를 풀기 위해, 온실의 온도·습도·토양 습도·조도·양액을 **자동으로 조절하는 스마트팜**을 파이썬으로 시뮬레이션하는 프로젝트입니다.

- **입력:** 작물 종류, 온도, 습도, CO2 농도, 토양 습도, 조도
- **출력:** 냉난방, 습도 조절, 구역 격리(차폐), 급수, 인공조명, 비료 살포
- **핵심 기능:** 적정 온습도·조도 유지, 비료량 조절, 병충해 피해 최소화

기획 내용은 [`main.md`](main.md)에 있습니다.

## 1. 설치하기

필요한 프로그램은 **Python**, **Git**, 그리고 코드 편집기인 **VS Code** 세 가지입니다. 화면은 파이썬에 기본으로 들어 있는 `tkinter`로 그리기 때문에 따로 설치할 라이브러리(`pip install`)는 없습니다.

### 1-1. Python 설치

1. <https://www.python.org/downloads/> 에서 최신 버전(3.10 이상, 개발은 3.14에서 함)을 받습니다.
2. 설치 첫 화면 아래쪽의 **`Add python.exe to PATH`를 꼭 체크**한 뒤 `Install Now`를 누릅니다.
   이걸 빼먹으면 터미널에서 `python` 명령이 안 먹힙니다.
3. 설치가 끝나면 터미널(시작 메뉴 → `PowerShell` 또는 `cmd`)을 **새로 열고** 확인합니다.

   ```bash
   python --version
   ```

   `Python 3.x.x`처럼 버전이 나오면 성공입니다.

### 1-2. Git 설치

1. <https://git-scm.com/downloads> 에서 Windows용을 받아 설치합니다. 설치 중 나오는 선택지는 **전부 기본값 그대로 `Next`** 를 누르면 됩니다.
2. 터미널을 새로 열고 확인합니다.

   ```bash
   git --version
   ```

### 1-3. VS Code 설치 (권장)

1. <https://code.visualstudio.com/> 에서 설치합니다.
2. 실행 후 왼쪽 네모 아이콘(Extensions)에서 **Python** 확장(Microsoft 제작)을 설치합니다.
3. VS Code 안에서 `` Ctrl + ` ``(숫자 1 왼쪽 키)를 누르면 아래에 터미널이 열립니다. 앞으로 나오는 명령은 여기에 입력하면 됩니다.

### 1-4. 프로젝트 내려받기

GitHub 계정이 없다면 <https://github.com> 에서 먼저 만들고, 팀장에게 **아이디를 알려줘서 저장소 협업자(Collaborator)로 초대**받으세요. 메일로 온 초대를 수락해야 코드를 올릴 수 있습니다.

```bash
# 코드를 둘 폴더로 이동 (예: 바탕화면)
cd Desktop

# 저장소를 내 컴퓨터로 복사 (처음 한 번만)
git clone https://github.com/Sol-Studio/26-2-OOP-1.git

# 복사된 폴더로 이동
cd 26-2-OOP-1
```

VS Code에서는 `파일 → 폴더 열기`로 이 `26-2-OOP-1` 폴더를 열면 됩니다.

## 3. 사용 방법

시뮬레이션은 **한 단계 = 10분**으로 저절로 흘러갑니다. 각 구역의 장치는 프로그램이 알아서 켜고 끄고, 사람은 **심기·수확·갈아엎기**만 합니다.

### 관리 패널
- **구역 카드 클릭** → 그 구역이 선택되고, 오른쪽에 생육 단계와 그래프가 나옵니다.
  - 빨간 값은 작물 적정 범위를 벗어났다는 뜻입니다.
  - 그래프의 초록 띠는 적정 범위, 회색 부분은 밤입니다.
- **🌱 심기** : 빈 구역에 아래 목록에서 고른 작물을 심습니다.
- **🧺 수확 / 정리** : 다 자란 작물을 수확하거나, 죽은 작물을 치웁니다.
- **수확 가능한 구역 모두 수확** : 이름 그대로입니다.
- **🚜 갈아엎기** : 자라는 중이든 병들었든 수확 없이 밭을 비웁니다.
- **로그** : `전체` 또는 구역별로 골라 볼 수 있습니다. 주황색 줄은 경고입니다.
- **⚙ 시뮬레이터 창 / 📱 모바일 앱** : 닫은 창을 다시 엽니다.

### 시뮬레이터
- **⏸ 정지 / ▶ 시작**, **10분 진행**(한 단계씩), **초기화**
- **속도** : 숫자가 작을수록 빠릅니다.
- **바깥 날씨** : 한파·폭염을 걸어서 냉난방이 잘 대응하는지 시험합니다.
- **병충해 발생** : 구역을 골라 병충해를 일으키면, 구역 격리 → 방제 → 해제 과정을 볼 수 있습니다.

### 모바일 앱
- **홈** : 수확 가능·주의 구역 수와 구역 목록. 구역을 누르면 상세 화면으로 갑니다.
- **구역** : 생장·건강, 환경 값 6개, 장치 상태, 수확·갈아엎기 버튼
- **알림** : 경고 로그 모음 (최근 것부터)

세 창은 항상 같은 구역을 가리킵니다. 한 곳에서 구역을 고르면 나머지도 따라 바뀝니다.

### `core/` — 모델 (객체지향의 핵심)

| 클래스 | 파일 | 하는 일 |
|-|-|-|
| `PlantProfile` | `plant.py` | 작물별 적정 조건 (온도·습도·EC 범위, 재배 일수, 생육 단계) |

## 5. Git과 GitHub 처음 쓰기

### Git이 뭔가요?

- **Git** : 내 컴퓨터에서 코드의 **변경 기록을 저장**하는 프로그램입니다. "게임 세이브 포인트"라고 생각하면 됩니다. 잘못 고쳐도 예전 세이브로 돌아갈 수 있습니다.
- **GitHub** : 그 기록을 **인터넷에 올려 팀원과 공유**하는 사이트입니다.

### 꼭 알아야 할 단어

| 단어 | 뜻 |
|-|-|
| 저장소 (repository, repo) | 프로젝트 폴더 + 변경 기록 전체 |
| 커밋 (commit) | 세이브 포인트 하나. "무엇을 왜 바꿨는지" 메시지를 붙임 |
| 브랜치 (branch) | 갈래. 내 작업을 다른 사람 작업과 섞이지 않게 따로 진행하는 공간 |
| `master` | 기본 브랜치. **항상 실행되는 상태**로 유지합니다 |
| push | 내 커밋을 GitHub에 올리기 |
| pull | GitHub의 최신 커밋을 내 컴퓨터로 받기 |
| PR (Pull Request) | "내 브랜치를 master에 합쳐 주세요"라는 요청. 팀원이 코드를 보고 합침 |
| 충돌 (conflict) | 두 사람이 같은 줄을 다르게 고쳐서 Git이 어느 쪽을 쓸지 모르는 상황 |

### 처음 한 번만 하는 설정

커밋에 누가 작성했는지 이름이 남습니다. GitHub에 가입한 이메일을 쓰세요.

```bash
git config --global user.name "내 이름 또는 GitHub 아이디"
git config --global user.email "GitHub에 가입한 이메일"
```

처음 `git push`를 하면 브라우저 창이 떠서 GitHub 로그인을 요청합니다. 로그인하면 그다음부터는 묻지 않습니다.

## 6. 매일 하는 작업 순서

**규칙: `master`에서 바로 작업하지 말고, 할 일마다 브랜치를 새로 만듭니다.**

```bash
# ① master로 가서 최신 코드 받기 (작업 시작 전 매번!)
git switch master
git pull

# ② 내 작업용 브랜치 만들기 (이름은 영어로, 무슨 작업인지 알 수 있게)
git switch -c add-pepper-crop

# ③ 코드 고치기 → 실행해서 잘 되는지 확인
python visualize.py

# ④ 무엇이 바뀌었는지 확인
git status          # 바뀐 파일 목록
git diff            # 바뀐 내용 자세히

# ⑤ 세이브할 파일 고르기 → 커밋
git add core/catalog.py
git commit -m "작물에 고추 추가"

# ⑥ GitHub에 올리기 (이 브랜치를 처음 올릴 때만 -u origin 브랜치이름)
git push -u origin add-pepper-crop
```

⑦ GitHub 저장소 페이지에 들어가면 노란 띠로 **`Compare & pull request`** 버튼이 보입니다.
   눌러서 무엇을 바꿨는지 적고 **`Create pull request`**.

⑧ 팀원이 코드를 확인하고 **`Merge pull request`** 를 누르면 master에 합쳐집니다.
   합쳐진 뒤에는 ①부터 다시 시작하세요.

### VS Code로 하고 싶다면

왼쪽의 갈래 모양 아이콘(Source Control, `Ctrl + Shift + G`)에서 같은 일을 버튼으로 할 수 있습니다.
- 파일 옆 **`+`** = `git add`
- 위 입력칸에 메시지 쓰고 **`✓ Commit`** = `git commit`
- **`Sync Changes`** / **`Publish Branch`** = `git push` / `git pull`
- 왼쪽 아래 상태 표시줄의 브랜치 이름을 누르면 브랜치를 바꾸거나 새로 만들 수 있습니다.

### 좋은 커밋 습관

- **작게, 자주** 커밋하세요. "기능 하나 = 커밋 하나"가 좋습니다.
- 메시지는 **무엇을 했는지** 알 수 있게: `ai`, `수정` ❌ → `토마토 적정 온도 범위 조정` ✅
- 커밋 전에 **꼭 실행해 보세요.** 안 돌아가는 코드를 master에 합치면 모든 팀원이 멈춥니다.
- 비밀번호, 개인 정보, `__pycache__/` 같은 자동 생성 파일은 올리지 않습니다. (`.gitignore`에 적힌 파일은 Git이 무시합니다.)

## 7. 자주 겪는 문제

**`python`을 찾을 수 없다고 나와요 / Microsoft Store가 열려요**
Python 설치 때 `Add python.exe to PATH`를 체크하지 않은 경우입니다. 설치 파일을 다시 실행해 `Modify`로 체크하거나, 지우고 다시 설치하세요. 설치 후에는 터미널을 새로 열어야 합니다.

**`git push`가 `rejected` 되며 거절돼요**
GitHub에 내가 아직 받지 않은 커밋이 있다는 뜻입니다. `git pull`로 받은 다음 다시 `git push` 하세요.

**`git pull` 후 `CONFLICT`(충돌)이 났어요**
당황하지 말고 VS Code로 해당 파일을 엽니다. 이런 표시가 보입니다.

```
<<<<<<< HEAD
내가 고친 내용
=======
다른 사람이 고친 내용
>>>>>>> master
```

VS Code가 위에 띄워 주는 `Accept Current`(내 것) / `Accept Incoming`(상대 것) / `Accept Both`(둘 다) 중 하나를 누르거나 직접 맞게 고친 뒤, `<<<<<<<` `=======` `>>>>>>>` 표시가 모두 없어졌는지 확인하고:

```bash
git add 충돌난파일.py
git commit
```

잘 모르겠으면 혼자 해결하려 하지 말고 팀원에게 물어보세요. 같은 파일 같은 부분을 여러 명이 동시에 고치지 않도록 **작업 전에 누가 무엇을 할지 나눠 두면** 충돌이 크게 줄어듭니다.

**커밋하기 전에 고친 내용을 전부 되돌리고 싶어요**

```bash
git restore 파일이름.py      # 그 파일을 마지막 커밋 상태로 (고친 내용은 사라짐!)
```

**지금 어느 브랜치에 있는지 모르겠어요**

```bash
git branch          # * 표시가 붙은 것이 현재 브랜치
git log --oneline   # 최근 커밋 목록 (q를 누르면 빠져나옴)
```
