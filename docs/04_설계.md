# 4. 디자인(설계)

## 4-1. 전체 구조: 모델과 화면 분리

```
core/   ← 모델: 스마트팜이 "어떻게 동작하는가" (tkinter를 모름)
ui/     ← 화면: 모델을 "어떻게 보여주는가"
```

- 화면 없이 `python main.py`로 모델만 돌려 볼 수 있다 → 제어 로직을 따로 시험하기 쉽다.
- 창(관리 패널·시뮬레이터·모바일·시세·CCTV)은 모두 **같은 `Farm` 객체 하나**를 보고 그린다.
- 로그인도 같은 원칙: 계정 확인은 `core/auth.py`(`Accounts`), 화면은 `ui/login/window.py`(`LoginWindow`)가 맡는다.
- 창·위젯·메뉴의 전체 체계는 [03_메뉴구조도.md](03_메뉴구조도.md) 참고.

## 4-2. 클래스 설계

| 클래스 | 파일 | 책임 | 주요 속성 / 메서드 |
|-|-|-|-|
| `PlantProfile` | plant.py | 작물별 **적정 조건** | 온도·습도·토양 습도·EC·CO2 범위, 최소 조도, 재배 일수, 수확량 / `stage()` |
| `PlantState` | plant.py | 식물의 **현재 상태** | 건강도, 생장도, 병충해, 생존 / `update()` |
| `Weather` | weather.py | **바깥 날씨** | 기온, 햇빛, 구름 (하루 주기) / `update()` |
| `EnvState` | environment.py | 온실 안 **환경** | 온도, 습도, CO2, 토양 습도, 조도, EC / `update()` |
| `Sensor` (+6) | sensors.py | 환경을 **측정** | 온도·습도·CO2·토양·양액·조도 센서 / `read()` |
| `SensorPanel` | sensors.py | 센서 묶음 | `read_all()` → `Readings` |
| `Device` (+8) | devices.py | 장치 하나가 **스스로 켤지 판단** | `control()`, `contribute()`, `power` |
| `Devices` | devices.py | 구역 장치 묶음 | 전력·물·비료 누적 사용량 / `effects()` |
| `FarmSection` | section.py | **구역 하나** (제어의 중심) | 환경·식물·센서·장치·격리 여부 / `process()`, `plant()`, `harvest()`, `plow()` |
| `Farm` | farm.py | **농장 전체** | 구역 6개, 시간, 날씨, 시장, 수확 기록 / `process()`, `harvest()`, `replant()` |
| `Market` | market.py | 작물 **시세** | 많이 팔면 내려가고 시간이 지나면 회복 / `sell()`, `step()` |
| `Accounts` | auth.py | **로그인 계정** 확인 | 아이디 → (솔트, 해시), 연속 실패 횟수 / `login()`, `add()`, `locked` |

## 4-3. 클래스 관계 (포함 관계)

```
Farm
├── Weather
├── Market
└── FarmSection × 6
    ├── EnvState ── PlantProfile
    ├── PlantState
    ├── SensorPanel ── Sensor × 6
    └── Devices ──── Device × 8
```

## 4-4. 상속: 장치 계층

```
Device                        control() · contribute() · power
├── OnOffDevice               decide() → 켜기/끄기 (히스테리시스)
│   ├── Heater      난방
│   ├── Cooler      냉방
│   ├── Humidifier  가습기
│   ├── Dehumidifier 제습기
│   └── Fan         환기팬
├── GrowLight                 밝기 0~1 단계 조절
└── DosingDevice              1회 투입량(amount) + 누적량(total)
    ├── Irrigation  급수
    └── Fertilizer  비료
```

- **다형성**: `FarmSection`은 장치 종류를 몰라도 `for d in devices: d.control(...)` 한 줄로 모든 장치를 제어한다.
- 새 장치를 추가할 때 `Device`를 상속해 `control()`만 만들면 된다 → 기존 코드 수정 없음.
- 센서도 같은 방식: `Sensor`를 상속해 `measure()`만 바꾼다.

## 4-5. 한 단계(10분)의 처리 흐름

```
Farm.process()
 1. 시간 +10분, Weather.update()      바깥 기온·햇빛 변화
 2. Market.step()                     시세가 기준가로 서서히 회복
 3. 구역마다 FarmSection.process()
    ① EnvState.update()               날씨 + 켜진 장치 효과로 환경 변화
    ② PlantState.update()             적정 범위 이탈 → 스트레스 → 건강도·생장도
    ③ 죽었거나 빈 구역 → 장치 모두 끔
    ④ 병충해 처리                       감지 → 격리 → 방제(성공/실패) → 해제
    ⑤ SensorPanel.read_all()          센서 측정
    ⑥ Device.control() × 8            장치별 자동 판단 + 로그
 4. 자동 수확·재파종 (옵션)
```

## 4-6. 장치 제어 규칙

| 장치 | 켜는 조건 | 끄는 조건 |
|-|-|-|
| 난방 | 온도 < 적정 하한 | 온도 > 하한 + 1°C |
| 냉방 | 온도 > 적정 상한 | 온도 < 상한 − 1°C |
| 가습기 | 습도 < 하한 | 습도 > 하한 + 5% |
| 제습기 | 습도 > 상한 | 습도 < 상한 − 5% |
| 환기팬 | 온도 > 상한 + 2°C 또는 CO2 범위 이탈 | 온도·CO2 정상 복귀 / **격리 중엔 항상 닫음** |
| 인공조명 | 06~22시, 자연광 < 최소 조도 | 모자란 만큼만 밝기 조절 |
| 급수 | 토양 습도 < 하한 | 적정 범위 중간까지 한 번에 급수 |
| 비료 | EC < 하한 | 적정 범위 중간까지 한 번에 살포 |

켜는 기준과 끄는 기준을 다르게 둔 이유(**히스테리시스**): 기준값 근처에서 장치가 10분마다 켜졌다 꺼졌다 반복하는 것을 막는다.

## 4-7. 로그인 설계

```
visualize.py
 └─ LoginWindow(root, on_success)        ui/login/window.py
      └─ submit()
           ├─ 빈칸 → 안내 메시지
           ├─ Accounts.login(아이디, 비밀번호)   core/auth.py
           │    ├─ 성공 → 실패 횟수 0, 로그인 화면 제거 → on_success(아이디) → App(root, 아이디)
           │    └─ 실패 → 실패 횟수 +1, 비밀번호 칸 비움
           └─ locked (5회 연속 실패) → 안내 후 종료
```

- **비밀번호를 원문으로 저장하지 않는다.** 아이디마다 무작위 솔트와 PBKDF2-SHA256(10만 회) 해시만 저장하고, 비교는 `hmac.compare_digest`로 한다.
- 로그인 화면은 별도 창이 아니라 **루트 창을 잠시 로그인 화면으로 쓰는 방식**이다. 성공하면 같은 루트 창에 관리 패널을 그리고, 이때 시뮬레이터·모바일 창이 만들어진다. 그래서 로그인 전에는 다른 창이 하나도 뜨지 않는다.
- 기본 계정: `farmer` / `evergrow`. 계정 추가는 `Accounts.add(아이디, 비밀번호)`.

## 4-9. 식물 건강 모델

- 적정 범위를 벗어난 정도만큼 **스트레스**가 쌓인다 (온도 3°C, 습도 15%, 토양 10%, EC 0.5 벗어나면 각각 스트레스 1).
- 병충해가 있으면 스트레스 +1.5.
- 건강도 변화 = (1 − 3 × 스트레스) × 시간 → 0이 되면 고사.
- 생장 속도는 **빛**과 **건강도**에 비례하고, 수확기를 넘기면 계속 상한다.
- 덥고(22°C 초과) 습하면(85% 초과) 병충해 확률이 10배 이상 오른다.

## 4-10. 수업 개념과 코드의 대응

| 주차 | 수업 개념 | 에버그로우 코드 |
|-|-|-|
| 9주차 | 사용자 함수 · 구조화 프로그래밍 | `core/economics.py`의 계산 함수, 위젯마다 `draw_…()` 함수 하나 |
| 9주차 | 클래스 · 객체 · 인스턴스 변수 | 구역 6개 = `FarmSection` 객체 6개, 각자 `env_state`·`plant_state` 보유 |
| 9주차 | 클래스 속성 (Rabbit의 `shape`) | `Heater.key/label/power_kw`, `Accounts.MAX_FAILURES` |
| 10주차 | 생성자 `__init__` | 모든 클래스가 처음 상태를 `__init__`에서 설정 (`OnOffDevice`는 꺼진 상태로 시작) |
| 10주차 | 캡슐화 | `_advance()`·`_handle_pests()` 같은 내부 메소드, 읽기 전용 `@property` (`ready`, `locked`) |

| 10주차 | 상속 · 오버라이딩 · 다형성 (Shape / shapeList 예제) | `Device` ← 장치 8개, `Sensor` ← 센서 6개, 창 클래스 ← `tk.Toplevel` (`super().__init__`) |
